# Qwen-Image-2.1 GGUF 推理性能与生成调优工程 Wiki

> 本文档记录基于 Apple Silicon (Mac MPS) 环境下，运行 Qwen-Image-2.1 GGUF 模型的推理调优、参数对比、算法适配以及功耗温控实战经验。

## 一、 模型架构与数学范式基础

### 1. 架构定位：流匹配（Flow Matching / Rectified Flow）
- **范式代差**：Qwen-Image-2.1 与 FLUX 属于新一代**整流流匹配（Rectified Flow）**模型，而非传统的基于 VP-SDE 的高斯扩散模型（如 SD 1.5、SDXL）。
- **数学轨迹**：
  - 传统扩散模型：噪点到数据的转移遵循指数对数信噪比（Log-SNR）的弯曲轨迹。
  - 流匹配模型：噪点到数据的转移为直线的速度场（Velocity Field: $v_t = x_1 - x_0$）。
- **重要推论**：任何针对传统弯曲 SDE 曲线设计的二阶非线性多步求解器（如 `dpmpp_2m`、`dpmpp_sde`）以及针对非线性噪声衰减设计的调度器（如 `karras`、`exponential`），在流匹配模型上**不可直接套用**。

## 二、 采样器与调度器（Sampler & Scheduler）实验矩阵

在固定双人复杂全身坐姿提示词下，实测不同参数组合的表现：

| 实验编号 | 步数 (Steps) | 采样器 (Sampler) | 调度器 (Scheduler) | 画面表现 | 工程原理解析 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Exp-01** | 25 | `euler` | `normal` | 结构完整细腻，肢体分明 | **基准高精度状态**：积分步长极小。**实测总耗时 1379s (~23.0 分钟)**，平均约 55.1s/步，Mac 持续高负载发热。 |
| **Exp-02** | 12 | `euler` | `normal` | 人物肢体严重融合，胸部与下肢融化粘连 | **步长超限（Overshooting）**：12 步对于双人全身这一高复杂度任务而言，自注意力层（Self-Attention）未能完成空间解耦便仓促结束。 |
| **Exp-03** | 15 | `dpmpp_2m` | `karras` | 彻底崩坏成彩色磨砂玻璃/纯未去噪噪波 | **数学公式打架（ODE 积分严重发散）**：`dpmpp_2m` 与 `karras` 硬编码了高斯扩散的曲率假设，作用在直线流匹配上导致积分彻底跑偏，未完成去噪。 |
| **Exp-04** | **18** | **`euler`** | **`normal`** | **清晰完整，五官肢体稳定，背景透视良好** | **👑 黄金平衡点（Sweet Spot）**：**实测总耗时 987s (~16.4 分钟)**。耗时精准下降 **28.4%**（节省整整 6 分半钟高热满载时间），画质与解剖结构高度稳定。 |

### 关键调优铁律：
1. **Flow Matching 模型必须锁定**：`euler`（或 `euler_cfg_pp`）作为采样器，`normal` 作为调度器。
2. **任务复杂度决定最低有效步数**：
   - 单人半身/特写肖像：12 ~ 14 步即可稳定收敛；
   - 双人/多人全身复杂透视：建议最低保持在 **16 ~ 18 步**。

| 监控指标 | 闲置待机 (Idle) | 生成中 (Inference) | 调优影响与工程结论 |

| **单步平均耗时** | - | **55s ~ 75s / 步** | 耗时主要由 Apple Silicon 显存带宽与核心数决定。步数每降低 1 步，直接减少约 1 分钟的高温满载时间。 |

## 四、 降温与降功耗实操指南（工程落地）

1. **步数压缩**：
   - 调试构图阶段：设为 12~14 步（快速看大效果）；
   - 复杂画面定稿：设为 18 步（省去 25 步最后 7 步边际效应递减的漫长等待）。
2. **系统级频率截断（DVFS 甜点策略）**：
   - 开启 macOS 的「低电量模式（Low Power Mode）」，限制 GPU 冲上最高能耗比不划算的极高频，功耗可骤降 30% 以上，机身温度显著改善。
3. **分辨率策略**：
   - 构图测试：768 × 768（Token 数降低约 44%，速度翻倍，温度大幅降低）；
   - 终稿输出：1024 × 1024。

## 五、 Git 仓库与版本管理规范（推荐模板）

当将此工程推送至 GitHub 私有仓库时，务必使用以下 `.gitignore` 规范，避免误提交几十 GB 的模型权重：

```gitignore
# 忽略大模型权重文件
models/diffusion_models/*.gguf
models/diffusion_models/*.safetensors
models/text_encoders/*.safetensors
models/vae/*.safetensors

# 忽略输出图片缓存
output/*.png
output/*.jpg

# 忽略虚拟环境与系统缓存
.venv/
__pycache__/
*.pyc
.DS_Store
```

只需提交：
- `docs/`（本 Wiki 文档与技术总结）
- `workflows/`（调优后的 ComfyUI 流程 JSON）
- 自定义脚本或 Python 插件代码
